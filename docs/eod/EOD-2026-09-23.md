### Cancel-then-book (the resource actually transfers) — M-booths ONLY
A booth is a capacity-1 Google resource; the holder's hold reserves it, so *just adding* the requester's
booking left its room resource **auto-declined** (Rico "kept" the room). Fix (Howard-confirmed): on consent
Finalize **cancels the holder's hold INSTANCE for that date** (frees the resource) then books the requester
→ clean transfer, no strikethrough. Book Session captures the hold's event-instance id onto the row;
Finalize's `Cancel Hold?` (kind=MBOOTH && id) → `Cancel Hold` (Calendar DELETE, fail-safe) → Book Requester.
**Studios untouched** — preempt still move-then-books.
