## "Availability check did not run": root cause + fix (LIVE)

Traced every instance from 24 Sep (runs **11136** Studio 8, **11029** Studio 7). Same pattern both times:

1. **The model glued visible junk onto a timestamp**: `window_end: "…17:00:00+08:00ភាsa"` and
   `"…+08:00容器id"`. The `clean()` scrubber only strips *invisible* characters (added after the 30 Aug
   U+FE0F incident), so Room Availability correctly answered `BAD_WINDOW`.
2. **The model then retried cleanly in the same turn and got the room back free**, but Guard Probe
   refused if **any** availability call that turn failed. It threw away a correct, checked summary.
   **Both refusals were false positives.**

The wording was also wrong for users: it says "did not run" (it ran and failed), uses "availability
check" (meaningless to a requester), and forces a throwaway "ok" reply before Jessie re-checks.

**Fixes:**
- **#1: junk-proof timestamps** (Room Availability **v8**, Book Session **v44**). New `isoOnly()` keeps
  the leading ISO date/time and drops trailing junk for `start_iso` / `end_iso` / `booking_date`. Both
  real inputs from 24 Sep now parse on the first call.
- **#2: no false alarms** (main **v153**, Guard Probe). A failed call only counts when no availability
  call that turn succeeded; for the offered room, the latest answer wins. A busy answer superseded by a
  free re-check stands; free then busy is still refused.
- **#3: plain-language fallback** (main **v153**) for the rare real case: *"Before you confirm, let me
  make sure Studio 8 is free at that time. Reply "check" and I will confirm it, or give me a different
  time."* Removing the reply step entirely (auto re-check) would need a loop in main; not worth it once
  the false positives are gone.

With #1 and #2, neither 24 Sep refusal would have fired. **Verified:** test-nodes **170/170** (+3 guard
cases including the exact BAD_WINDOW-then-OK pattern, +5 `isoOnly` cases) on candidates and `--live`;
`check-fromai` clean; imported and confirmed via pull; all active. Logged as **CLAUDE.md gotcha 16**.
