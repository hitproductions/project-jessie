## 5. Consent engine (#3) — COORDINATED DEPLOY + PROVEN LIVE END-TO-END (supersedes §2–§3)

Later in the day the consent engine went from "built and isolated" (§2–§3) to **deployed and proven
live end-to-end** for the book-preempt path. Drove the full flow through Slack (self-authorized QA)
and verified it on the calendar: a Celebrity Recording into an occupied Studio F **preempted** a VO
incumbent — Open wrote the PENDING row + DMed the incumbent + told the requester → the incumbent
**consented and moved** their own booking via the normal Move flow → Move's **tail hook** matched the
row → **Finalize placed** the requester in the freed slot. End state: incumbent relocated + the
higher-priority booking placed, **no double-book**. Later re-ran clean after the fixes: proper summary
with the "current holder" note → Finalize **Return Done** → requester got **"Done - Studio F is yours"**
and the incumbent a "moved to make way" notice.

**Five bugs found + fixed live to get there** (all imported, verified stored, `health`/`verify-ids`/
`test-nodes --live` green). Live versions now: **main v147, Book v35, Move v16, Finalize v6, Open v3.**

1. **Consent Sheets nodes must reference the tab by numeric gid (`431550013`), not by name.** The Sheets
   *append/update* op resolves the sheet by gid; `mode:list value:"Consent Requests"` fails
   `Sheet with ID Consent Requests not found` (only *read* tolerates the name). Fixed all six consent nodes.
2. **`Read Pending Consent` / `Read Consent Rows` need `alwaysOutputData:true`.** With the correct
   (usually empty) consent tab, a 0-row read makes n8n skip everything downstream — **silently killing
   the whole main workflow** after Read Pending Consent (success, no reply) and truncating Move before
   Return Moved. The old by-name read accidentally hit a non-empty sheet and hid this. The dangerous one:
   an empty consent tab took Jessie fully dark.
3. **Decide Preempt must carry `reference_data` into `reqPayload`** (else Finalize's server-side replay
   of the requester's Book rejects `NO_REFERENCE_DATA`).
4. **Finalize `Book Requester` (executeWorkflow) must map `reference_data`** — it forwarded 13 fields but
   not this one, and executeWorkflow only passes mapped keys.
5. **Finalize `Placed Book?` must match `CREATED`, not `BOOKED`** — Book Session's success token is
   `CREATED`, so a real placement was mis-classified as a failure (row marked FAILED, requester told
   "couldn't place" when the event had in fact been created).

**Also:** removed the "Automated with this n8n workflow" footer on the five consent message nodes
(`includeLinkToWorkflow:false`). **Cleaned up** all test events (INCUMBENT + CELEBTEST6/7 on Studio F
2027-11-08, cancelled via Jessie's own Cancel flow — calendar clear).

**Findings opened (PENDING.md):** **26** the agent can *fabricate* a preemption claim without calling

Name` which Open stores empty → "…  moved their session" with a blank name.
