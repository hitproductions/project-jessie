## The pivot

- **Decided: Jessie becomes a Slack app** built with Block Kit. Typing stays for the first message and for questions;
  everything that books or changes goes through a form or a button. No launch date is set, and no deadline talk goes into
  the docs (removed from CLAUDE.md, PENDING, the launch checklist, the status doc and the 12 Oct EOD).
- **Review docs:** `docs/design/slack-forms-pivot.md` (the case, with an evidence section) and
  `docs/design/slack-app-before-after.html` (a before / after page for review, with Slack screen mockups).
- **Review feedback taken in:** focus on structure first (before / after per feature, so nothing is lost); a client list
  can exceed Slack's 100-option limit; treat every requester as a booker; "book a room" rather than "book a session"; a
  button menu in the DM (like an existing internal Slack app); n8n's Crypto node (HMAC-SHA256) with the webhook's Raw Body
  for Slack's signature check, so no server change is needed.
- **Compared with Slack's Google Calendar app** ("Create event", "Available times"): its form pattern is worth copying,
  but it schedules people on personal calendars, with none of Jessie's room rules, titles, client checks or approvals.

## Decided in the design session (afternoon)

The running record is **`docs/design/slack-app-processes.md`**: every current feature mapped to the form version (keep /
gain / lose / change). The before / after presentation will be made from it.

- **Front door:** a DM menu, no Home tab. **Book a room · My bookings · Studios.** Shown on a greeting or anything not
  understood, at the end of each result (⋯), and on "menu". No "next booking" line for now.
- **AI:** reads the first message (to pre-fill a form or find a booking) and answers questions, with a short follow-up
  window. Typed cancel / move: the AI finds the booking, then shows it with buttons.
- **Studios (day board):** each room's free and taken times (no titles), date picker, filter, previous / next day, one Book
  button per room. "Free all day" = nothing booked in the whole 24 h; free times offered 8 AM - 11 PM.
- **Book a room:** step 1 date, start, end, "What's it for?", Repeats; step 2 the room (free rooms that fit, ranked from
  Airtable Session Types Priority / Last Resort, top one recommended) and the details.
- **Details:** fields shown by the requester's department (Airtable Booking Defaults) and the session type. Client typed
  freely and matched on Book ("Did you mean ...?", new names allowed). Engineer from Slack's people picker, pre-filled from
  a nickname in the first message. Booking type as Client work / Internal / Personal. Localization by project code from the
  Localization Projects table. Booking for someone else behind a checkbox. The calendar title assembled by code from the
  fields (project in ALL CAPS for post and music; Localization codes as written).
- **Cancel and move:** My bookings (made + tagged, next 7 days; "See all upcoming" opens a scrollable form); Cancel with
  Slack's confirm pop-up; Move opens a pre-filled form; cancel a whole series (needs a series id written on each event);
  a Department bookings view for coordinators as a nice-to-have.
- **Results after Book (proposed):** the form turns into "Booking..." then "Booked" or the problem with entries kept; the
  DM gets the result with Move / Cancel; the room's read-back shown as a status that updates.
