## The pivot

- **Decided: Jessie becomes a Slack app** built with Block Kit. Typing stays for the first message and for questions;
  everything that books or changes goes through a form or a button. No launch date is set, and no deadline talk goes into
  the docs (removed from CLAUDE.md, PENDING, the launch checklist, the status doc and the 12 Oct EOD).
- **Review docs:** `docs/design/slack-forms-pivot.md` (the case, with an evidence section) and
  `docs/design/slack-app-before-after.html` (a before / after page for review, with Slack screen mockups).
- **Review feedback taken in:** focus on structure first (before / after per feature, so nothing is lost); a client list
  can exceed Slack's 100-option limit; treat every requester as a booker; "book a room" rather than "book a session"; a
  button menu in the DM (like an existing internal Slack app); n8n's Crypto node (HMAC-SHA256) with the webhook's Raw Body
  for Slack's signature check, so no server change is needed.
- **Compared with Slack's Google Calendar app** ("Create event", "Available times"): its form pattern is worth copying,
  but it schedules people on personal calendars, with none of Jessie's room rules, titles, client checks or approvals.

## Decided in the design session (afternoon and evening)

The running record is **`docs/design/slack-app-processes.md`**: every current feature mapped to the Slack-app version
(keep / gain / lose / change). **Every section is agreed.**

- **Front door:** a DM menu, no Home tab. **Book a room · My bookings · Studios.** Shown on a greeting or anything not
  understood, at the end of each result (⋯), and on "menu". No "next booking" line for now.
- **AI:** reads the first message (to pre-fill a form or find a booking) and answers questions, with a short follow-up
  window. Typed cancel / move: the AI finds the booking, then shows it with buttons.
- **Book a room:** step 1 date, start, end, "What's it for?", a small Repeats checkbox; step 2 the room (free rooms that
  fit, ranked from Airtable Session Types Priority / Last Resort, top one recommended; a note names usual rooms not free
  then) and the details. A ⋯ on the step-2 date line holds the rare options: *Show all suitable rooms* (adds Last Resort
  rooms, booked without a second refusal) and *Pair with a vocal booth*.
- **Paired rooms:** sessions that need a booth (Localization Dubbing) are offered studio + booth pairs from Airtable's
  Paired with; Celebrity Recording gets a holding-rooms checklist; no booth by default otherwise.
- **Details:** fields shown by the requester's department (Airtable Booking Defaults) and the session type. Client typed
  freely and matched on Book ("Did you mean ...?", new names allowed). Engineer from Slack's people picker, pre-filled from
  a nickname in the first message. Booking type as Client work / Internal / Personal. Localization by project code from the
  Localization Projects table. Booking for someone else behind a checkbox. The calendar title assembled by code from the
  fields (project in ALL CAPS for post and music; Localization codes as written).
- **After Book:** the form stays open and turns into "Booking..." then "Booked", or the problem with entries kept; the DM
  gets the result with Move / Cancel; the room's answer shows as a status that updates. **PENDING 44: a booking the room
  declines is deleted** - the calendar never keeps a refused booking.
- **Series:** Repeats adds how often, which days, and an end (a number of occurrences, 2-16, or a date); step 2 lists every
  date with ✓ / ⚠️ and its own ⋯ (skip, room, time); the button says "Book N dates". **Move or cancel a whole series**
  (needs a series id on each event).
- **Finding out:** Studios day board (free and taken times, no titles; "free all day" = nothing booked in 24 h; free times
  offered 8 AM - 11 PM; one Book button per room). Typed questions answered in code with Book buttons: a whole day gets the
  board, part of a day the per-room list. My bookings built by code (replaces PENDING 100).
- **Cancel and move:** My bookings (made + tagged, next 7 days; "See all upcoming" opens a scrollable form); Cancel with
  Slack's confirm pop-up; Move opens a pre-filled form; a Department bookings view for coordinators as a nice-to-have.
- **Approvals and notices:** Approve / Decline buttons; the booking's engineer may answer too, first answer wins (PENDING
  80); the requester can withdraw or confirm "already cleared"; fixes PENDING 27, 78, 79 by design. The engineer is told of
  every new booking. Reminders: studio sessions the day before; M booths and conference rooms in one weekly message, Monday
  9:00 AM, standing M booth holds included.
- **Behind the scenes:** an Interactions log of every click and submission; during QA the date pickers open a year ahead
  (typed messages keep the existing shift); one recipient filter for the launch `DEV_REDIRECT` flip; the new Slack URLs go
  into the Cloudflare exemption rule; form flows tested by people, checked from the logs.
