## 1. Recurring bookings — Stage 1 (live, verified)

Individual events per date (never a native Google recurring event), so each is
movable/cancellable alone. Chosen: **Option A**, shipped as a staged quick-win.

- **NEW `Jessie — Expand Series`** (`hkx9PXcgW9nrzY2a`): computes the occurrence dates from a
  pattern (frequency, weekday codes, start, count/until, all-day/times). Enforces an end is
  required, span ≤ 1 year, ≤ 16 for now. **The model passes the pattern, never the dates.**
- **Book Session `series` flag:** a series must be confirmed even for M booths (the
  immediate-book bypass is single-booking only). Locked with 5 new offline gate tests.
- Verified end to end on year-shifted dates: "M3 every Tuesday for 4 weeks" → the four correct
  **Tuesdays** (Sep 21, 28, Oct 5, 12), one confirmation, four independent all-day M3 events,
  `series=true`, claim backed by Guard Probe.

**Issues found in testing and how they were resolved:**
- *Auto-booked without asking me to confirm.* The M-booth immediate-book rule won over the
  prompt. **Fixed** deterministically — the `series` flag requires confirmation even for M booths.
- *Booked daily instead of every Tuesday.* The model did the date math and misread the pattern.
  **Fixed** by moving date math into `Expand Series` — the model now only extracts the pattern.
- *"An error happened" on confirm.* `Expand Series` returned "unavailable": a workflow created
  via the API defaults to `active:false` and isn't callable as a tool, with no execution record
  to point at. **Fixed** (activated it); recorded as CLAUDE.md gotcha 0.

**Stage 2 (deferred):** move the create loop server-side (`Book Series`) so the model calls it
once — full loop determinism. Tested logic is in `workflows/drafts/recurring/`; the only piece
left is the n8n sub-workflow-loop node config, which needs the n8n UI to verify. Until then the
loop is model-driven over correct dates (worked cleanly in test, not yet bulletproof).
