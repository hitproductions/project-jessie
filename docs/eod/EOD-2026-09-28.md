## Prepare Booking — the eval report's option 2 (built; main not yet imported)

The model gathers details; **code renders the summary the requester approves**, in one fixed format with
the calendar title first and a check code at its foot. At the yes, main reads that exact message back,
verifies the code, and Book Session books those details — whatever the model sends. A yes to a summary
that did not come from Prepare Booking is refused (`NOT_PREPARED`). Before it: 5 date formats, the title
shown in 16% of summaries, and one live booking titled differently from the summary approved. **v163
eval: title shown in 96 of 98 summaries, 95 of 98 prepared** (the 3 were series, not yet prepared).

Also built into the same path: no date named → ask (QA E1); start time only → the session type's Typical
Duration (QA M4); department from the session type ("Music or Audio Post?" only when it can be either);
real free alternatives when a room is taken (PENDING 23); a holding-room note for Celebrity Recording
(PENDING 30); Localization titles always `Project Code / initials`.

**Speed.** v163 made summary turns ~4.5 s slower — not Prepare itself (3.1 s) but the model still doing
its own four lookups first, which Prepare then repeated. v164/v165 remove that: the prompt says nothing
needs looking up first, Prepare works out department and booking type, and Book Session reuses the staff
list main has already read. The v165 eval measures the result.
